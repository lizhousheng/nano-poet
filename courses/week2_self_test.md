# Week 2 答案

## 一、模型基础

**1.1** vocab_size = 9563 是清洗后的唐诗文本里**所有不同字符的总数**——所有出现过的汉字 + 标点 + 换行符。`set(text)` 收集所有不同字符，`len()` 数有多少个。不用 BPE 是因为：BPE 实现复杂（要训练合并规则），而中文字符级粒度本身就很合理（一个汉字本身就有意义，不像英文 "tokenization" 需要拆子词）。Week 1-3 选简单的，先把 pipeline 跑通。

**1.2** `nn.Embedding(9563, 192)` 是一张 (9563, 192) 的查找表。输入：(B, T) 形状的字符 ID 张量；输出：(B, T, 192)——每个 ID 被替换成对应那一行的 192 维向量。本质上就是一个矩阵 + 索引查找，但 PyTorch 帮你做了梯度反传，让表里的数字可学习。

**1.3** 不加位置信息，attention 是**完全对称的**——`[床, 前, 明, 月]` 和 `[月, 明, 前, 床]` 给模型看起来完全一样（因为 attention 只算"位置 i 看位置 j"的相似度，没有"位置 i 在第几个"的概念）。位置信息让模型知道"床在月之前"。

**1.4** 相加而不是拼接，是因为：拼接会让 embedding 维度翻倍（192 → 384），所有后续层都要变大，计算成本翻倍。而相加在数学上等价于"让模型自己学习如何分离位置和内容信息"——只要 token_emb 和 pos_emb 在向量空间里学到正交的方向，模型完全可以分别解码。**经验上证明：加法足够，没必要拼接**。

---

## 二、Self-Attention 核心

**2.1** 用**三个独立的线性层** `W_Q`、`W_K`、`W_V`（每个都是 (n_embed, head_size) 的可学习矩阵）从同一个 embedding 投影出来：

```
Q = W_Q @ x
K = W_K @ x  
V = W_V @ x
```

不能共用是因为这三个角色任务完全不同：Q 是"我想找什么"，K 是"我能匹配什么"，V 是"我能贡献什么内容"。共用就失去了"角色分离"——模型没有灵活性学习"以不同视角看待同一个字"。

**2.2** `Q @ K.T` 算出来形状是 `(B, T, T)`。`scores[i][j]` = 位置 i 的 Query 和位置 j 的 Key 的点积 = "位置 i 想从位置 j 取多少信息"的原始分数。

**2.3** 不除 √dk，scores 数值会随 dk 增大而变大（标准差 = √dk）。softmax 输入数字差距大时会**一边倒**（一个位置吃 99% 权重，其他全 0），导致：(a) 信息瓶颈，模型只看一个位置；(b) 梯度消失，softmax 输出接近 0/1 时对输入的导数接近 0。除以 √dk 把 scores 压回标准范围，让 softmax 输出平滑可学。

**2.4** **-inf 而不是 0** 是因为 softmax 里有 `e^x`：`e^(-inf) = 0`，权重严格为 0；而 `e^0 = 1`，仍然会分到权重。**上三角而不是下三角**是因为：score 矩阵里 `scores[i][j]` 表示"位置 i 看位置 j"，列号 > 行号（上三角）对应"看未来"，违反自回归原则；列号 < 行号（下三角）对应"看过去"，允许。

**2.5** softmax 把任意数字变成"加起来等于 1 的概率分布"。**非要 softmax 的原因**：(a) 保证权重非负（不能用"负相似度"）；(b) 保证权重和为 1（变成真正的"注意力分配"）；(c) 放大差异（让相关位置权重显著高于不相关位置）；(d) 处处可导（梯度下降的基本要求）。直接用 scores 加权会出现负权重、权重和不固定等问题，模型学不动。

**2.6** `weights @ V` 是按注意力权重**加权求和 V**。用 V 而不是 K 或 Q 是因为：Q 和 K 是"匹配工具"（决定谁和谁相关），V 是"内容载体"（被读取的实际信息）。`weights[i][j]` 决定位置 i 从位置 j 取多少，**取的是 V[j] 的内容**。Q/K 用完就丢了，V 才是真正传递到下一层的信息。

---

## 三、多头机制

**3.1** 单头：用一组 W_Q/W_K/W_V，只能学一种"看上文的方式"。多头：用多组 W_Q/W_K/W_V 并行跑 attention，每组学不同的关注模式（一头可能学押韵，一头学对仗，一头学意境等）。**好处**：同样总参数量下，模型能同时关注多个维度，表达能力强得多。

**3.2** head_size = 192 / 6 = **32**。这样设计是为了让"多头总参数量 ≈ 单头同 n_embed 的参数量"——多头不靠加参数取胜，靠**关注模式的多样性**取胜。

**3.3** 6 个头各输出 (B, T, 32)，先**拼接**回 (B, T, 192)，然后过一个 `nn.Linear(192, 192)` 投影层（代码里叫 `self.proj`）做最后的混合。这个投影层让多头信息互相交融，不只是"6 个独立结果"。

---

## 四、Block 结构

**4.1** 两个子层：
- **Multi-Head Attention**：让不同位置之间**传递信息**（信息流动）
- **Feed Forward (FFN)**：对每个位置内部**做非线性加工**（信息加工）

attention 不改变位置数，FFN 不跨位置——两者职责完全分开。

**4.2** FFN = `Linear(n_embed → 4*n_embed) → GELU → Linear(4*n_embed → n_embed)`。中间扩展 4 倍是**经验值**：让模型在更高维空间"思考"（4 倍维度有更多组合可能），再压回原维度输出。研究表明 2-4 倍是甜区，原 Transformer 论文用 4，被广泛沿用。

**4.3** Residual connection: `x = x + sublayer(x)`，让原始输入 x 有一条"直通车"绕过子层。改成 `x = sublayer(x)` 会出现两个问题：(a) **梯度消失**——深层网络反向传播时梯度逐层衰减，6 层后几乎归零，深层学不动；(b) **信息丢失**——每层强制替换输入，浅层的有用信息可能在深层被覆盖。残差让"每层只做小修小补，主干信息保留"，是 ResNet 2015 年的关键发现，深度学习能做深的根本原因。

**4.4** LayerNorm：对每个 token 的 n_embed 维向量做归一化（减均值、除标准差），然后用可学习的 scale 和 bias 调整。作用：保证每层输入数值分布稳定，防止深层数值爆炸/消失。**Pre-LN**：`x + Sublayer(LN(x))`，先 norm 再处理。**Post-LN**（原论文）：`LN(x + Sublayer(x))`，先处理再 norm。我们用 Pre-LN，是 GPT-2 之后的标准做法，训练更稳定。

---

## 五、堆叠

**5.1** 单层只能做一次"attention + FFN"。多层让信息**层层加工**：浅层学局部模式（字搭配、词组），深层学全局结构（句法、语义、风格）。本质区别：多层让 attention 的"信息混合"可以**递归发生**——第 2 层的 attention 可以基于第 1 层已经混合过的信息再次混合，组合能力指数级提升。

**5.2** 6 层比 1 层 loss 低，是因为：(a) 容量更大，能记住更多模式；(b) 表达能力指数级提升，能学到 1 层学不到的高阶组合关系（比如"看到上文出现某个词组，预测当前位置该用什么字"）。每层学什么是模型自己决定的，研究员只能事后用可视化工具去"读"它。

**5.3** 6.37M 里大头是 **token_embedding + lm_head ≈ 2.4M**（9563 × 192 × 2 + lm_head 的 9563 × 192）——加起来占 38%。剩下 ~4M 是 6 层 Block 的 attention 和 FFN 参数。这是字符级 tokenizer 在中文上的代价——vocab 大，embedding 矩阵就大。换 BPE（vocab 缩到 8000）能省点，但不会戏剧性变小。

## 六、训练动态

**6.1** train loss 下降 = 模型在学习训练集上的规律。val loss 同步下降 = 学到的规律泛化到了验证集（**真正在学知识**，而非死记）。**过拟合开始**的信号：train 继续降，但 val 不再降甚至反弹——意味着模型从"学规律"变成了"死记训练集"。我们的 v0.3 在 step 6000 左右出现这个信号。

**6.2** 这种 val loss 在某个区域徘徊、然后突然又能下降的现象，叫**"鞍点逃逸"** 或 **"损失景观平台期"**。原因：模型卡在 loss 曲面的一个相对平坦区（不是最优点，但梯度很小所以走得慢），靠 AdamW 的**动量项**积累足够的"惯性"才能挣脱，进入新的下降通道。**工程教训**：loss 平稳几百步不要立刻停，可能后面还有突破。

**6.3** `model.eval()` 切换模型到推理模式：关闭 Dropout（生成时不要随机丢激活）、固定 BatchNorm 统计量（虽然我们没用 BN）。`torch.no_grad()` 关闭梯度计算：生成时不需要反向传播，关掉省 50%+ 显存、提速 1.5-2 倍。两者配合是 PyTorch 推理标准操作。

**6.4** Bigram 用 1e-2 因为：模型结构极简（一个 Embedding），损失曲面平缓，大 lr 能加速。Attention 模型用 3e-4 因为：模型结构复杂、深，损失曲面崎岖，大 lr 会让梯度更新跨过谷底导致震荡甚至发散。**经验法则**：模型越深越大，lr 越要小。GPT-3 的初始 lr 才 1e-4 左右。

## 七、生成

**7.1** 自回归生成流程：(1) 给起始上下文 → (2) forward 一次得 logits → (3) 取最后一个位置的 logits / 温度 → (4) softmax 转概率 → (5) `multinomial` 采样一个字 → (6) 拼到序列尾巴 → (7) 回到 (2) 循环。**每生成一个字都要重新跑整个模型**——这就是 Transformer 推理慢的根本原因。**优化方案叫 KV Cache**：把之前计算过的 K/V 缓存起来，避免每步重算。我们目前没实现这个，Week 4 会讲。

**7.2** 温度公式：`logits = logits / temperature`，然后再 softmax。数学效果：
- T = 1.0：原始分布不变
- T < 1（如 0.7）：logits 数值放大 → softmax 输入差距变大 → 输出更尖锐 → 高概率字占绝对优势 → 保守
- T > 1（如 1.5）：logits 数值缩小 → softmax 输出更均匀 → 低概率字也有机会 → 随机

直观：温度低 = 模型"专注高概率路径"；温度高 = 模型"放飞自我"。

**7.3** `argmax` 是**贪心**：每次必选概率最高的字。结果：(a) 完全确定性，相同起始字永远生成相同诗——无创意；(b) 容易陷入循环（"花花花花..."），因为某些字在某些上下文里概率最高，会自我强化。**`multinomial`** 按概率分布采样，让低概率字也有机会被选中，输出更多样、更像自然语言。

## 八、工程纪律

**8.1** `idx[:, -self.block_size:]` 截断保留最后 128 个 token。原因：模型的 `position_embedding` 只学了 0~127 这 128 个位置的向量。如果上下文超过 128，第 128+ 个位置没有对应的位置向量，要么报错要么用错位置。截断是最简单的应对（虽然丢了最早的上下文）。**生产模型用 RoPE 等位置编码方案能外推到训练时没见过的长度**，但那是更高级的话题。

**8.2** `nn.Parameter` 是模型的**可学习参数**——会出现在 `model.parameters()` 里，被优化器更新，随模型 `.to(device)` 自动搬到 GPU。`register_buffer` 是模型的**常量张量**——不在 `parameters()` 里（不更新），但**也会随模型 `.to(device)` 搬到 GPU**。`tril` 是个固定的下三角矩阵，永远不变，所以用 buffer 而不是 Parameter。

**8.3** 深层模型对初始化敏感的原因：每层的输出经过 6 层后，方差会**累积放大或缩小**。PyTorch 默认初始化（Linear 用 Kaiming）是为单层设计的，6 层堆起来后初始 logits 可能偏离合理范围（要么过大要么过小）。N(0, 0.02) 是 GPT-2 经过实验确定的"适合深层 Transformer"的初始化方差，配合残差连接和 LayerNorm，让初始 forward 时数值分布稳定。**信号**：初始 loss 接近 `log(vocab_size)` 说明初始化合理；偏离太多说明哪里不对。

# 准备进 Week 3

Week 3 我们要做四件事，让现在的 v0.3 从 val 4.14 推到 3.5 附近（理论估计），生成质量再上一个台阶。**注意：是优化训练过程，模型结构基本不变**。

**Week 3 内容预告**：

1. **学习率调度**（lr scheduling）—— 训练初期用大 lr 快速下降，后期用小 lr 精细调整。GPT 类模型的事实标准：**Warmup + Cosine Decay**。

2. **梯度裁剪**（gradient clipping）—— 防止单步梯度过大把训练打飞。一行代码 `clip_grad_norm_`，但救命。

3. **混合精度训练**（mixed precision / AMP）—— 用 float16 算 forward/backward，float32 存权重。T4 上能**提速 2-3 倍，省一半显存**。免费午餐。

4. **权重衰减**（weight decay）—— AdamW 里的 W，对模型权重施加 L2 惩罚，**防过拟合的标配**。我们之前其实有用，但没讲。

学完这四样，你写的训练循环就**和工业级训练代码 95% 相似了**。剩下 5% 是分布式训练（多卡），那是 Week 5 以后扩规模时讲。
